01 Programmer Fundamentals

Language- and framework-agnostic skills that make you a better developer everywhere. These compound over time — every Angular concept you learn sticks faster when these are solid. Learn them in Phase 0, reinforce them in every phase after.

Must Have — non-negotiable for any serious developer
Good to Have — differentiators that separate good from great
// Thinking & Problem Solving
MUSTProblem Decomposition

Break any problem into smaller solvable pieces before touching code. The #1 separator between junior and senior thinking.

MUSTDebugging Mindset

Isolate → reproduce → hypothesize → test. DevTools breakpoints, network tab, memory profiler — not just console.log.

MUSTReading Errors & Stack Traces

Read the actual error before Googling. Most errors tell you exactly what's wrong — train yourself to hear them.

GOODFirst Principles Thinking

Strip assumptions, reason from the ground up. Ask "why does this work" not just "does this work." Rare and powerful.

// Code Quality & Craft
MUSTClean Code Principles

Meaningful names, small functions, single responsibility. Code is read 10x more than written. Write for the next developer.

MUSTDRY & KISS

Don't Repeat Yourself. Keep It Simple. Know when abstraction helps and when it just adds indirection without value.

MUSTSOLID Principles

Not as theory — as practical refactoring decisions. Spot SRP and OCP violations in real code reviews. Apply them daily.

MUSTCode Review Skills

Give and receive feedback professionally. Know what to look for: logic bugs, naming, duplication, edge cases, performance.

GOODRefactoring Patterns

Extract method, rename variable, replace conditional with polymorphism. Improve code without changing behavior — deliberately.

GOODCode Smells Recognition

Long methods, God classes, magic numbers, deep nesting. Know the smell and know the fix. Becomes automatic over time.

// Data Structures & Algorithms (Practical Level)
MUSTArrays, Objects & Maps

Master JS/TS array methods: map, filter, reduce, find, flat, flatMap. Know when to use Map vs Object vs Array for lookup speed.

MUSTBig O — Basic Awareness

Not for grinding LeetCode — for writing sensible code. Know O(1), O(n), O(n²). Spot the nested loop before it causes lag.

MUSTRecursion & Tree Traversal

UI is a tree. DOM is a tree. Angular's component tree is a tree. Recursion unlocks working with hierarchical data naturally.

GOODSorting & Binary Search (Concept)

Why sort algorithm choice matters with large datasets. Binary search logic applied to frontend lookup problems.

GOODStacks, Queues & Linked Lists

Less critical for frontend, but understanding these structures makes you a stronger problem solver in any context.

GOODHash Maps & Sets

Duplicate detection, frequency counting, O(1) lookup optimization. Practical in real frontend data processing tasks.

// Version Control & Collaboration
MUSTGit — Branching Strategy

Feature branches, PR workflow, rebase vs merge (know the difference), resolving conflicts deliberately. Go beyond add/commit/push.

MUSTConventional Commits

feat, fix, refactor, chore, docs. Your commit history is documentation. Write it like someone will read it — because they will.

MUSTPR Best Practices

Small focused PRs. Good descriptions. Respond to reviews professionally. This is your visible craft on any team.

GOODGit Internals (Light)

What HEAD, index, and working tree mean. Makes rebase, cherry-pick, and reset far less scary when things go wrong.

// Communication & Professional Skills
MUSTTechnical Communication

Explain complex decisions to non-technical stakeholders. Write clear PR descriptions and technical docs. Rare and highly valued.

MUSTAsking Good Questions

"I tried X, failed because Y, I think the issue is Z — am I right?" is 10x more effective than "it doesn't work." Saves everyone's time.

MUSTEstimation & Blocker Communication

Estimate with ranges not points. Communicate blockers early. Know when to push through vs when to ask for help.

GOODMentoring Mindset

Teaching forces deep understanding. Even as a learner, explaining concepts to others sharpens your own knowledge faster than any tutorial.

// Systems Thinking & Web Fundamentals
MUSTHow the Web Works

DNS → TCP → HTTP → Browser rendering pipeline. What happens from URL to painted pixels. Every frontend dev must know this end-to-end.

MUSTREST API Fundamentals

HTTP verbs, status codes, headers, request/response cycle. Know what makes a good vs bad API contract as a consumer and collaborator.

MUSTBrowser & Event Loop

Call stack, microtasks vs macrotasks, memory management basics. Makes async bugs and performance issues finally make sense.

MUSTSecurity Fundamentals

XSS, CSRF, CORS, HTTPS, secure token storage. Know enough to not accidentally ship a vulnerability in production.

GOODCore Design Patterns (5)

Observer, Strategy, Factory, Facade, Singleton. Not to memorize — to recognize when you're already using them without knowing it.

GOODBasic SQL Literacy

SELECT, JOIN, WHERE, GROUP BY. Enough to read a query, discuss data shapes, and collaborate meaningfully with backend teams.

// Tooling & Developer Efficiency
MUSTIDE Mastery (VS Code)

Keyboard shortcuts, multi-cursor, extensions: ESLint, Prettier, GitLens, Angular Language Service. Your editor is your workshop — know it cold.

MUSTTerminal & CLI Comfort

Navigate dirs, search files, pipe commands, run npm/ng scripts. Fear of the terminal slows every developer. Eliminate it in Phase 0.

MUSTBrowser DevTools — Deep

Network, Performance, Memory, Sources, Application tabs. Use all of them — not just the Console. This is your primary debugging weapon.

GOODDocker Basics

Pull, run, build an image, docker-compose basics. Enough to run your app in a container and understand the team's deployment setup.

03 Phase Roadmap
00
Phase Zero
Programmer Foundations Sprint
Weeks 1–2 · Setup Phase
Before going deep on Angular, spend 2 weeks locking in the must-have programmer fundamentals. These habits will make every phase after this faster, stickier, and more professional.
  • JS/TS Core SolidifyClosures, prototypes, event loop, Promises vs async/await, generics, utility types
  • Problem Decomposition DailyPick 3 real work problems. Write breakdown on paper before coding. Start this habit now, carry it forever.
  • Git Workflow UpgradeSet up conventional commits, practice interactive rebase, squash merges, resolve conflicts deliberately
  • DevTools Mastery Sprint30 min on each tab: Network, Performance, Memory, Sources, Application. Know every panel by Week 2.
  • Clean Code Chapters 1–5Read and immediately apply one principle per day to code you write that same day at work
  • Web Request LifecycleDraw: URL → DNS → TCP → HTTP → Parse → Render → Paint. Know every step and what can go wrong at each.
🎯 Goal

End of Week 2: You explain the event loop clearly, write clean TypeScript with proper types, use Git branching professionally, and debug with DevTools instead of console.log. These habits carry into every single phase.

01
Phase One
Angular Core — Solidified
Weeks 3–6
Stop assuming you know these. Understand them at the level where you can explain every decision to a junior developer without hesitating.
  • TypeScript for AngularGenerics, utility types (Partial, Pick, Omit), type narrowing, interfaces vs types in practice
  • Component ArchitectureSmart vs dumb, Input/Output, lifecycle hooks — when each fires and why. Not just memorized, explained.
  • Change Detection — DeepDefault vs OnPush. Break it intentionally. Fix it. Explain why you'd choose OnPush in a code review.
  • RxJS FundamentalsObservable, Subject, BehaviorSubject, switchMap, mergeMap, combineLatest, takeUntil, async pipe
  • Services & DIprovidedIn root vs module, hierarchical injectors, singleton patterns, service composition
  • Routing EssentialsLazy loading, route guards, resolvers, child routes, route parameters, query params
🚀 Build

Task Manager App — Full CRUD with lazy loaded feature modules, OnPush change detection throughout, shared state via service, route guards, resolvers, and 3+ RxJS operators used meaningfully. Clean commits, good PR descriptions, no spaghetti.

02
Phase Two
State, Forms & Async Mastery
Weeks 7–10
The topics most Angular devs avoid. This is the senior-level jump. These concepts need building — not just reading — to click permanently.
  • Angular Signalssignal(), computed(), effect() — modern reactive primitives. Understand when to use over RxJS and why.
  • NgRx EssentialsStore, Actions, Reducers, Effects, Selectors. Learn the pattern first. The library second. Never reversed.
  • Reactive Forms MasteryFormGroup, FormArray, custom validators, async validators, dynamic form generation from config
  • RxJS Advanced PatternsError handling, retry/catchError, shareReplay, higher-order observables, memory leak prevention
  • HTTP & InterceptorsHttpClient, request/response interceptors, global error handling, retry logic, centralized loading states
  • Performance BasicstrackBy, CDK virtual scrolling, defer blocks, webpack-bundle-analyzer, preloading strategies
🚀 Build

Upgrade Task Manager — Add NgRx for global state, reactive forms with custom async validators, HTTP interceptor for auth + global retry logic, virtual scrolling on the task list, defer blocks for heavy components. Refactor old Phase 1 code using new knowledge.

03
Phase Three
Scale, Patterns & Architecture
Weeks 11–14
Think in systems, not components. These make enterprise Angular apps maintainable at scale and make you sound and act like a senior in every room.
  • Module & Standalone ArchitectureFeature/core/shared modules, standalone components, NX monorepo awareness, when to migrate what
  • Design Patterns AppliedFacade (wrapping NgRx), Repository (API layer), Adapter — in real code not slides. Recognize then implement.
  • Component Reusabilityng-content projection, dynamic components, ControlValueAccessor — the most underused Angular feature
  • CSS ArchitectureBEM, CSS custom properties, ViewEncapsulation, design tokens, scalable responsive systems
  • Testing FundamentalsUnit tests for components/services, TestBed, mock strategies, testing NgRx effects, testing reactive forms
  • Frontend System DesignHow to design a scalable Angular app: modularization, state strategy, API layer abstraction, auth architecture
🚀 Build

Enterprise Dashboard — New project from scratch: multi-feature dashboard, proper standalone architecture, a custom ControlValueAccessor form control, reusable component library (table, modal, toast, skeleton loader), unit tests for 3+ critical components and services.

04
Phase Four
Performance & Security
Weeks 15–17
Enterprise non-negotiables. These don't just improve your apps — they signal professional maturity in every code review, architecture discussion, and interview.
  • Core Web VitalsLCP, CLS, INP — what they measure, how Angular affects them, how to improve with real tooling
  • Angular Performance ProfilingChrome DevTools Performance tab, Angular DevTools, identifying slow change detection, zone.js awareness
  • Bundle OptimizationLazy loading, tree shaking, preloading strategies, analyzing and reducing bundle size in real Angular projects

05
Phase Five
Interview Readiness
Weeks 18–20
Zero new topics. Convert 5 years of real experience and 17 weeks of deep practice into articulate, confident answers backed by code you've actually built.
  • Angular Q&A — Out LoudTop 30 Angular interview questions. Answer verbally, not in writing. Record yourself. Painful but essential.
  • Programmer Fundamentals Q&AEvent loop, Big O basics, SOLID, design patterns — framed around your actual Angular code, not abstract theory
  • System Design PracticeDesign an Angular app from scratch — modularization, state, API layer, auth, performance. 30-min whiteboard drills.
  • Your 3 War Stories (STAR)Hard bug solved, performance win, architecture decision. Specific, numbered results. Practiced until natural.
  • Portfolio PolishClean READMEs, deployed on Netlify/Vercel, code quality cleaned up, screenshots/demos. Make it hireable.

✅ Finish Line

You walk into any interview and can: explain Angular's change detection with tradeoffs, design a scalable state strategy, explain SOLID using examples from your actual code, discuss Big O in the context of a real Angular problem you solved, and answer "tell me about a hard problem" with a specific, compelling story — not a vague answer.

04 Learning Strategy
🔨

Build First, Look Up Second

Start every topic by building something broken. The moment you hit a wall is exactly when the learning happens — not before it.

🎯

The 20% Rule

20% of Angular + programmer concepts cover 80% of real work. This plan targets exactly that 20%. Everything else, look up when you need it.

📦

One Project, Many Concepts

Every concept goes into a real project with real stakes. Not an isolated tutorial file. Stakes make concepts permanent.

🔄

Friday Refactor & Review

Every Friday: no new topics. Refactor this week's code. Write 3 things learned. Resolve the one thing still unclear. Advance only from clarity.

🗣️

Teach to Lock In

After every topic, explain it out loud in plain English. If you can't explain it simply, you've only heard it — you haven't learned it.

⏱️

Timebox Everything

Max 20 min stuck before Googling. Max 30 min reading before building again. Overthinking is procrastination with good intentions.

06 Anti-Tutorial Hell Rules

❌ Stop Doing This

  • Watching full courses before starting to build
  • Reading docs end-to-end "just to understand"
  • Switching topics because something got hard
  • Bookmarking tutorials to watch "later"
  • Rebuilding the same todo/counter app again
  • Waiting until you "feel ready" to start
  • Learning DSA in isolation with no application
  • Consuming multiple sources on the same topic

✅ Start Doing This

  • Start building immediately, look up when stuck
  • Read only the doc section you need right now
  • Sit with difficulty — that's where growth lives
  • Ship something every week, even if imperfect
  • Apply clean code rules to code you write today
  • The discomfort of starting IS the actual learning
  • Use your day job as your primary learning lab
  • One source per topic — go deep, then move on
07 The 6 Unbreakable Rules
  • Never learn in isolation

    Every concept must land in real code within 24 hours of learning it. Heard ≠ learned. Applied = learned.

  • No phase-skipping

    Don't jump to NgRx before component architecture is solid. Don't jump to patterns before state management clicks. Depth before breadth, always.

  • One resource per topic, maximum

    Multiple sources on the same topic is procrastination wearing a productive disguise. One good source. Go deep. Build. Move on.

  • Imperfect and shipped beats perfect and pending

    Your project needs to exist, run, and demonstrate the concept — not pass a code audit. Iterate later. Ship now.

  • Your job is your best classroom

    Every ticket at work is a live lab with real stakes. Apply this week's concept to a real problem. That's the fastest learning there is.

  • Phase gate: teach before advancing

    Can you explain this topic clearly to a junior dev? Yes → advance. No → one more week. Depth is the entire point of this plan.
