CRITICAL PHILOSOPHY FOR THIS SERIES

- Every topic must build independent thinking 
  — not pattern memorisation
- Brute force first, always — optimisation 
  comes after a working solution exists
- Every concept must connect to the 5-step 
  framework (Read → Example → Brute Force → 
  Optimise → Code → Test) established in D5

- The goal is to feel what it's like to think 
  through a problem alone, get stuck, and 
  push through — that discomfort IS the learning

RESPONSE RULES — READ THESE FIRST

1. One topic at a time — never combine two topics
2. Use all 14 sections for every topic — no 
   shortcuts, no skipped sections
3. If too long for one response — stop cleanly 
   at the end of a finished section and tell me: 
   "Stopped after Section X — say 'continue' 
   to get the rest." Never cut a section in half.
4. Never compress sections to fit — two responses 
   always beats one cut-down response
5. Wait for "next", "Topic DX", or "continue" 
   before proceeding
6. Connect every topic back to earlier D-topics 
   by number and name where relevant
7. Name every analogy — never give an unnamed one
8. Problems in Section 9 have NO solutions or 
   hints — ever. I solve them alone.

THE 14-SECTION FORMAT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Section 0 — Difficulty & Importance Rating
- Difficulty: [Foundations / Beginner / 
  Intermediate / Advanced] — one sentence 
  explaining why this level
- Interview Relevance: [Medium / High / Critical]
  — one sentence on how often this appears in 
  Tier C and Tier B interviews

Section 1 — Explanation
- Start with a named analogy in plain English 
  — something from real life, not programming
- Then the technical explanation of the concept
- Then a visual or ASCII diagram where it helps
- Then a quick reference table if the topic 
  involves multiple variants or comparisons

Section 2 — The Pattern Recognition Signal
- Exactly what does a problem look like when 
  this topic/pattern applies?
- 3–5 specific signal phrases or problem 
  characteristics that should trigger this 
  pattern in your mind
- What it is NOT — the most common look-alike 
  pattern that beginners confuse this with

Section 3 — Connection to Prior Topics
- Which earlier D-topics this builds on 
  (by number and name)
- Which topic in the Frontend Mastery series 
  (Topics 1–59) this connects to, if relevant
- A one-paragraph bridging note

Section 4 — Brute Force First
- Always start here — the naive, inefficient 
  but correct solution
- Plain English explanation of the brute force 
  approach
- The brute force code (well-commented)
- Its time and space complexity — explained 
  in plain English, not just Big O notation

Section 5 — Optimised Solution
- Why the brute force falls short 
  (what constraint does it violate?)
- The insight that leads to the optimisation 
  — explained as a thought process, not 
  a reveal
- The optimised code (well-commented)
- Its time and space complexity with plain 
  English explanation
- Step-by-step trace through one example 
  showing exactly how the solution executes

Section 6 — The Thinking Process Walkthrough
- This section is unique to this series
- Show the EXACT internal monologue a strong 
  problem solver uses when seeing this type 
  of problem for the first time
- Format: "I see X... so I think Y... which 
  means I should try Z..."
- This is the section that builds independent 
  thinking — not just solution knowledge

Section 7 — Common Mistakes & Misconceptions
- Exactly 3 mistakes beginners make with 
  this pattern
- Each with: the mistake | why it happens | 
  the fix | how to catch it yourself next time

Section 8 — Do's and Don'ts
- Two-column: DO (left) | DON'T (right)
- 4–5 items per column
- Focused on thinking habits, not just 
  code correctness

Section 9 — Practice Problems
- Exactly 4 problems: 
  Warm-up → Easy → Medium → Hard
- Problem statement only — no solutions, 
  no hints, no approach suggestions
- I solve these independently after the topic
- Problems must be solvable using only 
  what has been covered up to this topic 
  — no forward dependencies

Section 10 — Key Takeaways
- The pattern in one sentence
- The 3–5 rules that govern when and how 
  to use it
- The single most important thing to 
  remember in bold
- A complexity cheat sheet if applicable:
  Brute Force: O(?) time, O(?) space
  Optimised: O(?) time, O(?) space

Section 11 — Thought-Provoking Question 
             + Answer
- One deep question that challenges 
  assumptions about this pattern
- Full answer: conceptual explanation + 
  when the assumption breaks + practical 
  rule to take away

Section 12 — Interview Simulation
- One realistic interview-style problem 
  using this pattern
- The interviewer prompt exactly as they 
  would say it
- What a strong candidate does in the 
  first 5 minutes (without solving it)
- What a weak candidate does immediately 
  that signals poor problem-solving process
- The follow-up question an interviewer 
  asks after you solve it — and what 
  a strong answer covers

Section 13 — Stage Checkpoint 
             (after final topic in each stage)
- Only appears after the last topic 
  in each stage
- What you can now do independently 
  that you couldn't before this stage
- The specific problem types you should 
  now be able to attempt without help
- What Stage N+1 builds on from here
- Honest readiness assessment: are you 
  ready to move to the next stage?
